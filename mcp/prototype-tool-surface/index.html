Q2. Response size

Example: faction_members for a faction with 100 members. Torn returns 12 fields per member, with two nested objects. The token counts are characters divided by four.

MCP results have two parts. The content text goes to the model. The structuredContent object goes to the client, and some clients also give it to the model. The question is which shape goes in each part.

Q3. Spec lookup

The lookup tools read the snapshot that ships in the package. They take no key, send no request, and never trigger the /key/info check. They still end with the budget line. A full describe_endpoint for /faction/{id}/members, with every schema reference resolved, is about 830 tokens. The 1.2MB spec file is about 300,000 tokens.

My lean, for you to accept or reject

Variant C. Five to seven hand-written Torn tools for the faction and war workflow, one generic torn_request for everything else, and three spec lookup tools. The default result is a compact table in content and the projected JSON in structuredContent. A fields argument narrows both. The full Torn response is never the default.
