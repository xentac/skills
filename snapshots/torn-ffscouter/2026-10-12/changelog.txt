FFScouter API changelog
Public API changes, newest first. Each entry is dated the day it shipped.
Change types: Added, Changed, Deprecated, Removed, Fixed. A Breaking tag marks changes existing clients may need to react to, such as a removed field, a changed field meaning, or values clients may depend on vanishing from an enum. Adding a value is not breaking.
2026-10-05
Added Admin-managed bounty target exclusions in OpenAPI contract 1.14.0. POST /api/v1/bounties/orders now rejects a direct player target that is on the exclusion list with code 99 and the message "This player cannot be targeted with bounties." Faction targets are unaffected, and existing open orders keep running. The list is managed from the admin panel only and is not exposed through the API.
Changed Bounty Board privacy guarantees are now documented in the contract. GET /api/v1/bounties/orders/{token} states that seller identities are returned only through that buyer-controlled token and never disclosed to other sellers or the public. The seller board, claims status, and claim submission operations state that only the caller's own claims, hits, and payouts are returned and buyer identity is never included. No response shapes changed and the contract version is unchanged.
2026-10-04
Added POST /api/v1/tornstats/key in OpenAPI contract 1.13.0. Stores or replaces the caller's TornStats API key with a registered FFScouter API key and queues a faction spy sync. Requires tornstats_api_key (TS_xxxxxxxx format) and consent_to_retrieve_and_store_tornstats_spies_self_and_faction set to true; consent_to_allowing_data_use_for_machine_learning is optional and defaults to false. Errors: 60 invalid TornStats key format, 61 required consent not accepted, 62 caller not in a faction, 63 TornStats rejected the key, 64 faction membership could not be verified. Rate limited to 3 requests per minute per account (code 20). The TornStats key and its masked form are never returned.
Added tornstats_integration_enabled and tornstats_key_in_place to GET /api/v1/check-key in OpenAPI contract 1.13.0. tornstats_integration_enabled is true when the key owner's TornStats key is active and contributing to faction spy sync; tornstats_key_in_place is true when a key is stored even if disabled or pending validation. Both are false for unregistered and demo keys. The TornStats key itself is not exposed.
Changed POST /api/v1/register code 6 now returns a specific reason. Signup reads Torn /key/info first, so a Public or Minimal key reports its Torn access type ("You provided a Public Only key. You should use a Limited or Full Key to sign up.") and a Custom key missing basic, battlestats, attacks, or hof reports the missing selection ("You are using a custom key missing the required permissions. Try using a Limited Key."). Permission rejections use source ffscouter. Other Torn key errors (incorrect key, federal jail, inactive, paused, insufficient access) return a short reason with source torn and torn_code, and "It has been removed from FFScouter." appears only when a stored key row was actually deleted. personalstats is optional. OpenAPI contract 1.12.0.
2026-09-30
Fixed GET /api/v1/check-key now returns the documented 400 JSON for a missing or malformed key (codes 1 and 2, source ffscouter) instead of failing with HTTP 500. OpenAPI contract 1.11.0.
Added source to every error response from POST /api/v1/register (codes 1, 2, 3, 4, 5, 6, 7, 8, 9). Code 6 reports source torn with torn_code when Torn returned an error, and source ffscouter for internal failures such as a concurrent registration. OpenAPI contract 1.11.0.
2026-09-28
Changed Breaking POST /api/v1/bounties/seller/claims now credits any eligible open bounty instead of only the submitted target, in OpenAPI contract 1.10.0. target_player_id and target_faction_id are now optional hints stored for display only and never restrict crediting; supplying both still returns code 97, and omitting both is allowed. Each qualifying Hospitalized hit in the last 24 hours is matched against a player bounty on the defender and/or a faction bounty for the defender's faction (the faction on the attack log at hit time), and the highest-paying eligible order wins. One open claim per seller is reused. Sellers still cannot earn on orders they placed or funded, on their own player, or on a faction they are a member of. A claim with no eligible open bounties returns code 91 with the message "No open bounties available."; codes 94 and 98 are no longer returned by this operation.
Removed monitoring_started_at from the POST /api/v1/bounties/seller/claims request body. The server always uses the 24-hour lookback window for qualifying hits. The response shape is unchanged, except that claim target fields are now the optional display hints (null when none was supplied).
2026-09-23
Added cancelled to the payout_status values on GET /api/v1/bounties/seller/claims/status recent_hits. A hit whose seller payout was cancelled (banned user or admin cancellation) was previously reported as pending; clients should show it as cancelled rather than still owed. OpenAPI contract 1.9.0.
2026-09-22
Added Faction targets to the Bounty Board in OpenAPI contract 1.8.0. POST /api/v1/bounties/orders and POST /api/v1/bounties/seller/claims accept target_faction_id as an alternative to target_player_id; supplying both returns code 97, and an unknown or empty faction returns code 96. A faction order has one shared pool of hits: hospitalizing any current member counts and reduces the pool by one. Faction membership is read from the Torn attack log defender faction. Sellers cannot claim a faction they are a member of (code 98). Order status adds target_faction_id, target_faction_name, target_faction_tag, and target_member_count (null for player orders), and each hit now includes the member actually hit as target_player_id and target_name. Seller board rows for faction targets add target_faction_id, target_faction_name, target_faction_tag, member_count, a capped members list with per-member estimates, members_truncated, and all_members_stronger, with disabled_reason = "member" when the seller belongs to the faction. Pending and history claims add target_faction_id (null for player claims).
2026-09-21
Added player_id to each transaction in GET /api/v1/account/faction/transactions, naming the player who caused the change (the depositor for deposits, the staff player for support adjustments). It is null when the change is not attributable to a player, such as an admin adjustment. OpenAPI contract 1.7.0.
Added Account balances API in OpenAPI contract 1.6.0. GET /api/v1/account/balance returns the Xanax-funded prepaid balance for the key owner, the deposit codes (deposit, factiondeposit), the current payment_value_per_xanax, and a faction object (full when the caller's role may view it, a restricted stub with can_view false when it may not, or null when not in a faction). GET /api/v1/account/transactions returns the 10 most recent personal transactions with no pagination. GET /api/v1/account/faction/transactions returns the 10 most recent faction transactions when the caller's role passes the faction view permission. Reads allow 70 requests per minute per account. Send Xanax with the message deposit to credit a personal balance or factiondeposit to credit a faction balance; both are case insensitive and any trailing text is ignored.
Removed POST /api/v1/account/withdraw. Withdrawals are no longer offered, so deposited value must be spent on FFScouter services.
Added Attack log details to each hit in GET /api/v1/bounties/orders/{token}: attack_id, attack_code, log_url (the Torn attack log link, null when unavailable), and ended_at (Unix seconds). Hits are returned newest first by ended_at. OpenAPI contract 1.5.0.
Added POST /api/v1/bounties/seller/policy/accept to accept the Bounty Board Data Policy and Rules with a registered API key. Requires key and i_have_read_rules_and_data_policy set to true, and must be accepted before the other seller endpoints and again after a policy update. Rejection returns code 95. Acceptance is written to the audit log. OpenAPI contract 1.4.0.
2026-09-20
Added Notes API in OpenAPI contract 1.3.0. GET /api/v1/notes lists notes visible to the key owner (personal, their faction's, and FFScouter team notes), with single-target, batch (targets, up to 205 player IDs), scope, and include_deleted filters, paginated up to 100 per page via page and limit. POST /api/v1/notes creates personal or faction notes and rejects targeting the caller's own player. POST /api/v1/notes/{uuid}/delete soft deletes. GET /api/v1/notes/info returns personal usage/limit and faction role, permissions, and usage. Content is plaintext printable ASCII (1 to 400 characters) and must be rendered as text, never as HTML, code, or links. Rate limited per account: 120 reads/minute, 10 writes/minute.
Added Optional referrer_player_id on POST /api/v1/bounties/orders, POST /api/v1/bounties/seller/claims, and POST /api/v1/losses/orders. It names the player who should receive the script commission for completed work. The recipient must be an approved commission recipient; invalid values and self-attribution (buyer, payer, or claimant) are ignored and normal bonus rules apply. Commission is a percentage of the service fee on finalized hits, capped at 50%, and is prepared for payout daily at 21:00 UTC. OpenAPI contract 1.2.0.
Added Bounty Board API in OpenAPI contract 1.1.0. Buyer (no key): GET /api/v1/bounties/orders/quote, POST /api/v1/bounties/orders, GET /api/v1/bounties/orders/{token}. Seller (registered key with accepted policy consent): GET /api/v1/bounties/seller/board, GET /api/v1/bounties/seller/claims/status, POST /api/v1/bounties/seller/claims.
Added Baseline of the documented public API, published as OpenAPI contract 1.0.0. Everything listed below is treated as established from this date; future entries record changes against it.

Flights: GET /api/v1/player-flights, GET /api/v1/player-flights/batch.
Activity: GET /api/v1/activity/player, GET /api/v1/activity/faction.

Losses: GET /api/v1/losses/orders/quote, POST /api/v1/losses/orders, GET /api/v1/losses/orders/{orderNumber}, GET /api/v1/losses/orders/{orderNumber}/upgrade/quote, POST /api/v1/losses/orders/{orderNumber}/upgrade, GET /api/v1/losses/seller/contracts, GET /api/v1/losses/seller/claims, GET /api/v1/losses/seller/orders/{orderNumber}, POST /api/v1/losses/seller/claim, POST /api/v1/losses/seller/claims/{claimId}/complete.
API Keys: GET /api/v1/check-key, POST /api/v1/register.
Targets: GET /api/v1/get-targets.
